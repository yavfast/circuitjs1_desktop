# Operating on a non-active document without disturbing the visible tab

## Context

Measured by the PL_AGA Phase 0 prototype (2026-10-01, scratch branch `proto/agent-bg-doc`, discarded), recorded in [agent-api.plan.md → Phase 0 result](../../../docs/agent-api.plan.md#PL_AGA_P0) and [PL_AGA_DEC_01](../../../docs/agent-api.plan.md#PL_AGA_DEC_01); the full R1/R2 rows, the path audit and offscreen rendering in [Phase 8 result](../../../docs/agent-api.plan.md#PL_AGA_P8) (live scenario `agent_bg`). Applies to any code that loads, undoes, exports, steps or renders a document that is not the active tab: SP_AGA_03_08 R1 (no disturbance) and R2 (the target behaves as if active).

## Key concepts

- **Session vs document.** `CircuitDocument` subsystems (simulator, editor, undo, adjustables, loader) resolve through their own document. Session coupling comes from direct `cirSim.*` calls: menu check items, the bars, `ColorSettings` voltage range, renderer transform and hint, the sliders dialog, the window title, menu item enablement, and the user's `CircuitJS1.onanalyze` hook (`CirSim.callAnalyzeHook`, reached from `preStampCircuit`): `DocumentScope` records the visible document (`CirSim.visibleWhileBound`) and the hook is skipped while another document is bound (PL_AGA Phase 5). The `ontimestep` hook (`CirSim.callTimeStepHook`, called after every timestep of `stepLoop`) is guarded the same way since PL_AGA Phase 7: a background run never calls it, a run of the visible document does.
- **Scoped silent bind.** Save the active tab's UI state (`saveUIState`), swap the bound document by field (`BaseCirSim.activeDocument` and `DocumentManager.activeDocument`), apply the target's options (`applyOptionWidgets`), its transform (or `centreCircuit()` if it has none) and its hint. Then run the operation, save the target's UI state and hint, swap back and re-apply the active tab's state. Finally refresh the derived widgets: `syncTimeStepBar`, `setPowerBarEnable`, `enableUndoRedo`, `allowSave(previous)` and `changeWindowTitle`. Cost measured: 0.6 ms average, 3 ms worst per bind. Since Phase 8 the scope also lays the target's scope panel out after the operation (`renderer.setCircuitArea()` + `scopeManager.setupScopes()`, circuit area reference put back), as the visible tab's next frame would.
- **Session-coupled paths (SP_AGA_03_08 list), audited in Phase 8:** exporters' options, load reset/options, adjustables, hint, centring, undo view, analysis request, stop state, modified flag/title — all routed by the scope (evidence in the plan). The file name/path setters (Phase 9: `CircuitInfo.setFile`, `BaseCirSim.setLastFileName`, `allowSave`, `CirSim.setUnsavedChanges`) act on the bound document's `CircuitInfo` and tab title; the window title and the Save item are session widgets that the scope exit re-derives/puts back for the visible tab. Console lines go to the bound document's log buffer by design.
- **Discarding a never-shown document.** A rejected `openFile(into: "new")` removes its new document with `DocumentManager.discardDocument` (no closed-tab dump, unlike `closeDocument`); its handle number stays used.
- **Offscreen render** (`CircuitRenderer.startOffscreen` → `OffscreenImage.step(deadline)`, driven by `agent/RenderOps` inside `DocumentScope`): bounds = element endpoints ∪ bounding boxes + 16 px, times scale; drawn in slices (background in ~1 Mpx bands, then elements, then posts/bad connections/scopes); re-measures when the element list changed between slices (keeps a same-size raster canvas). a measure pass into a 1 × 1 scratch canvas settles the bounding boxes first, so the canvas is allocated once, in a slice of its own; PNG via `canvas.toBlob` (off the event loop; no blob → `render_failed`), SVG via canvas2svg (`CirSim.loadCanvas2Svg`: shared, queued, no alert, retried after a failure).
- **`DocumentManager.dumpDocument`** (closed-tab dump, session save) binds through `DocumentScope` too (since PL_AGA Phase 1; before, it used the full `bindDocument`).

## Usage in this project

- Use the silent swap, never `BaseCirSim.bindDocument`/`CirSim.bindDocument`, for a background bind. `bindDocument` calls `setActive`, which stops the active tab's 16 ms `SimulationLoop` timer when the target is bound and restarts it, with a fresh 16 ms delay, on rebind. It also moves listeners, updates the toolbar run button and resets the renderer timers.
- Detach the session `SlidersDialog` while a background document is bound. `AdjustableManager.updateSliders` (`clearSlidersDialog` + `createSliders`, reached from load, import and undo) clears the shared dialog and refills it with the target's sliders. The target's rows are rebuilt by `restoreUIState → updateSliders` when its tab is activated.
- A sliced run (PL_AGA Phase 7, `agent/RunController`) steps the bound target with `CircuitSimulator.runSteps(observer, wireCurrentsEachStep)` — the free-running frame's timestep loop (`stepLoop`) without wall-clock pacing, speed bar or running-flag check; the observer records probes and ends the slice at its budget: `Slices.SLICE_MS` 20 − `SLICE_MARGIN_MS` 5 from before the scope entry (bind cost up to 3 ms, timer granularity, engine pauses — the prototype, timing inside the scope, measured 23–25 ms for a 20 ms budget). Then it yields through `Slices.afterVisibleFrame`: one session-wide queue for every run and render, releasing at most one slice per frame of a free-running visible tab (`SimulationLoop.runAfterNextFrame`, 50 ms fallback timer; a zero-delay `Timer` when the visible tab is stopped or owned by a run), round robin; continuations that do no slice (ended operation, closed document) do not use up a release. A fixed `schedule(1)` sometimes ran two slices back to back. Measured in Phase 8: active-tab rate 99–100 % of idle, run slices ≤ 18.3 ms.
- Harness diagnostics (not contracts): `CircuitJS1Agent.debugSetSliceProbe(fn)` (before/after every run/render slice), `debugSessionState()`, `debugCanvasPixels()` (synchronous render of the visible tab → PNG data URL), `debugClosedTabs()`, `debugDocState(handle).ui`, `debugFailNextSvgLoad()`.
- A busy document (`CircuitDocument.setAgentBusy(owner)`) is skipped by its own free-running loop, also when it is the visible tab; the run repaints it once per slice and resets `lastIterTime` at the end, so free-running resumes without catching up the run's wall time. User actions on it and its close call `cancelAgentRun()` first.

## Pitfalls

- **Drawing changes state.** A draw of a document is not read-only: `CircuitElm.updateDotCount` advances dot positions by `renderer.currentMult`; `ColorSettings.setPrintable` is set from the Printable item; `Scope.draw` resets its graph when the time step or its rect width changed (an in-circuit `ScopeElm` sets its rect from the renderer transform on every draw), advances the time base and trigger/history capture, fades 2-D plots, halves auto-range scales and refreshes an open properties dialog; element bounding boxes are recomputed (text extents). An offscreen draw must save and restore the transform values, Show Current, printable colours and `currentMult` (set 0), and draw scopes between `Scope.beginOffscreenDraw()`/`endOffscreenDraw()`. The user's image export (`drawCircuitInContext`) still has these side effects.
- **Layout needs no draw.** `checkLayout` (SP_AGA_02_16, `agent/LayoutOps`) lays the texts out through the elements' `layoutTexts` and measures them on the session's 1 × 1 measuring canvas (`CircuitRenderer.getTextMeasurer()`): no draw, no bounding box, no scope state, so a never-drawn background document gives the same boxes as the visible tab. Never derive text boxes from a draw.
- **Bounding boxes are draw-time state.** Most elements call `setBbox` in `draw()`, so a never-drawn background document keeps the endpoint rectangle of `ElmGeometry.initBoundingBox`; anything computed from `getBoundingBox()` (the simulator's `badConnectionList`, selection hit tests) can differ between the visible tab and a background document. Agent checks that need element extents use geometry only (`agent/SymbolOverlap`, 2026-10-04).
- **Background scopes have no sample buffers until laid out.** `Scope.undump` adds plots without `resetGraph`; only `setupScopes` (a frame of the visible tab) allocates them. Stepping a never-shown document with a multi-plot scope threw `TypeError` in `ScopePlot.timeStep` before Phase 8; `DocumentScope` now lays scopes out after every operation.
- **Scope auto-range scales are draw-dependent.** Fields 5–6 of an `o` line (`scale[V]`, `scale[A]`) are written by draws, so the text of a visible document differs from the same document operated in the background. Mask them in R2 comparisons.
- **Not interruptible within a slice:** one element draw (the first draw of a chip class in a session took 19 ms headless), one large raster canvas allocation (tens of megapixels: ~110 ms headless) and one timestep. Slices end on a deadline checked between items.
- **Per-operation yields are not enough.** Waiting for "the next frame" per operation lets every waiting operation continue after the same frame (a run and a render, or two runs, back to back). Queue all slices of the session in one place.
- **Engine pauses.** With a 3 ms slice margin single run slices reached 20.8–25.5 ms headless; `Slices.SLICE_MARGIN_MS` is 5 (14–18 ms slices), render slices stop 5 ms earlier still.

- Per-slice `bindDocument` with a 1 ms yield starved the active tab completely (0 % of its idle simulated-time rate). With a frame-aware yield it still cost 30 % of background throughput.
- The renderer hint (`hintType`, `hintItem1/2`) is session state and is not in the saved UI state. A normal tab switch carries the previous tab's hint items into the new tab and logs `getElm: invalid index`. Give each document its own hint (PL_AGA backlog).
- `CircuitSimulator.runCircuit` reads the speed bar through `cirSim.getIterCount()`. Stepping a background simulator without a bind uses the active tab's speed, and its console lines and element-level `CirSim` calls reach the active document.
- Log lines from session UI (for example `Save option: SlidersDialog.pos`) land in whichever document is bound. Do not compare raw log buffers in R2 checks.
- `ImportLifecycle` writes the time-step, speed, current and power bars directly. Restore them after the scope; `saveUIState` does not cover the time-step bar.
- `CircuitRenderer.centreCircuit()` calls `setCircuitArea()`, which sizes the session `circuitArea` from the *bound* document's scope count. Centring a background target leaves the visible tab's scopes at height 0 unless the area is restored (`DocumentScope` keeps the reference and puts it back; `restoreUIState` recomputes it on every tab activation). `ScopeManager.setupScopes` recomputes it only when that document's own scope count changes.
- Never set the time-step bar from code with `Scrollbar.setValue`: it runs the bar's command, which writes the quantised bar value (1-2-5 table capped at 10 µs) into the bound simulator's `maxTimeStep`/`timeStep` and calls `needAnalyze()`. `DocumentScope`, tab activation (`restoreUIState`) and the text/JSON importers use `ControlsDialog.syncTimeStepBar()` / `Scrollbar.setValueWithoutCommand` (thumb at the nearest position, label exact) since the agent-api fix round (SP_AGA_06_01 item 18, audit BL-D01); `updateTimeStepBar()` was removed. `ImportLifecycle`'s reset still uses `setValue` for the 5 µs default (a table value).
